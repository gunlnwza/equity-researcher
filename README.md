# equity-researcher

This is an MVP.

- Fetch evidence in parallel
- Have one model write the report
- Deterministically compile the report to PDF through LaTeX

The pipeline researches a public company, saves evidence by topic, generates an
equity-research report from that evidence, and renders the report as a PDF.

## Pipeline

```text
question set
    -> parallel web research
    -> cached Markdown evidence
    -> model-written Markdown report
    -> Pandoc + XeLaTeX
    -> PDF report
```

Evidence collection is concurrent, but bounded by `SEARCH_CONCURRENCY` to reduce
rate-limit pressure. Existing evidence files are reused instead of researched
again.

## Requirements

- Python 3.10+
- An OpenAI API key with access to the configured model and web search
- Pandoc
- XeLaTeX, typically installed through a TeX distribution

Python packages used by the main pipeline:

```bash
python -m pip install openai python-dotenv pyyaml
```

Install `pytest` to run the tests:

```bash
python -m pip install pytest
```

## Setup

Create a `.env` file in the project root:

```dotenv
OPENAI_API_KEY=your_api_key
```

Optional environment variables:

```dotenv
SEARCH_CONCURRENCY=3
LOG_LEVEL=INFO
```

`SEARCH_CONCURRENCY` must be at least `1`.

## Usage

Run the full question set for a ticker:

```bash
python main.py NKE --questions example
```

Use the smaller, cheaper question set during development:

```bash
python main.py NKE -q small
```

The question-set name resolves to `config/questions/<name>.yaml`. See
[config/README.md](config/README.md) for the schema and included presets.

## Outputs

For a run such as `python main.py NKE -q example`, the pipeline writes:

```text
data/NKE/
├── evidence/
│   ├── business_model.md
│   ├── competition.md
│   └── ...
└── output/
    ├── report.md
    └── report.pdf
```

Topic names from the question configuration become evidence filenames. The
report writer receives those files as source material and is explicitly told to
treat their contents as evidence rather than instructions.

## Caching and fresh research

If `data/<TICKER>/evidence/<topic>.md` already exists, that topic is skipped.
This makes repeated runs faster and cheaper, but it also means evidence can
become stale. Remove the specific evidence file when you intentionally want that
topic researched again.

## Tests

```bash
python -m pytest -q
```

The unit tests mock OpenAI calls; they do not require a live API request.

## MVP limitations

- Research quality depends on the configured questions and retrieved sources.
- Evidence freshness is controlled manually through the file cache.
- The report is generated by one model pass without a separate reviewer.
- PDF rendering requires local Pandoc and XeLaTeX installations.
- This is a research prototype, not investment advice or an autonomous trading
  system.
